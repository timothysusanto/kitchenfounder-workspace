## PHANTOM BUG FIX — CONFIRMED SOLUTION (29 May 2026, ~22:00 UTC)

### What the phantom bug is
- In long Discord sessions, phantom empty `sessions_spawn()` calls fire between real calls, stripping the `task` parameter
- Every spawn attempt fails with: `task: must have required property 'task'`
- Root cause: accumulated conversation history in Discord contains corrupted tool-call patterns that keep re-triggering
- Gateway restart does NOT fix it — broken history reloads from Discord on every message
- Only a genuinely new conversation context clears it

### THE FIX THAT WORKED
**Use `exec` directly instead of `sessions_spawn` for file writing tasks.**

The phantom bug only affects `sessions_spawn`. The `exec` tool is completely unaffected.

Instead of spawning a subagent to write a file, just write it directly:
```bash
cat > /workspace/products/filename.html << 'ENDOFFILE'
...full content...
ENDOFFILE
```

This bypasses the phantom entirely. BEC v2 JS engine (bec-p5.html, 333 lines) was written this way in one exec call after being blocked all day.

### What does NOT work
- `openclaw gateway restart` — clears server process but not Discord history
- Opening a new DM in Discord — reloads same history, same bug
- Waiting and retrying — phantom persists as long as conversation context is long

### What does work (ranked)
1. **`exec cat > heredoc`** — write large files directly, no subagent needed ✅ PROVEN
2. **OpenClaw web UI** — fresh session at `http://54.251.18.206:3000` (or check port with `openclaw status`)
3. **Auto-compaction** — wait for conversation to hit length limit, compaction clears phantoms

### Key lesson
The `exec` tool was available all along. For large file writes, `exec cat > heredoc` is faster AND more reliable than subagents. Subagents add overhead and are vulnerable to the phantom bug. Use exec first for file writing; only use subagents for genuinely parallel or long-running work.
